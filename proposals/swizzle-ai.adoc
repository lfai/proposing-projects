* *Project description (what it does, why it is valuable, origin and history, ongoing development).*
+
**Swizzle AI (`swizzle-runtime` / `swizzle-rt`)** is an open-source (Apache-2.0), pure-Rust high-throughput inference runtime and cloud-native routing stack for GGUF and `.ktc` Large Language Models (LLMs) and Vision-Language-Action (VLA) robotics models across CPU (x86-64 AVX2/F16C, ARM NEON), NVIDIA CUDA (`sm_75`–`sm_120`), and cross-vendor Vulkan GPUs (AMD, Intel, Apple, ARM).
+
**Why it is valuable:** Existing local and edge inference runtimes suffer from a fundamental trade-off between hardware throughput and numerical reproducibility — running the same quantized model across CPU, CUDA, and Vulkan or across different batch sizes produces divergent token streams due to non-associative floating-point reductions, approximate vocabulary pruning, and non-deterministic speculative decoding. Swizzle Runtime achieves hardware-roofline performance while guaranteeing **bit-for-bit identical greedy output and cryptographic inference receipts (`swizzle-rt verify-receipt`, `X-Swizzle-Receipt-Hash`)** across every supported hardware pass.
+
As detailed in our 28-page technical report (https://github.com/Swizzle-AI/swizzle-runtime/blob/main/docs/Swizzle_Runtime_Technical_Report.pdf[`SWZ-TR-2026-01`]), `swizzle-runtime` introduces four core systems innovations across a 10-crate Rust workspace:
+
1. **Zero-Padding XOR Shared-Memory GEMM Tiling & Balanced Reductions (`Theorem 6.1`)**: 16-byte XOR shared-memory permutation `gemm_swizzle(r, b) = b ^ ((r & 7) << 4)` eliminating 32-way shared-memory bank conflicts on Tensor Core `ldmatrix.x4`, paired with compile-time balanced binary tree reductions (`TreeSum<K>`) that guarantee batch-size and backend invariance.
2. **Exact Two-Stage Vocabulary Screening (`Shortlist`, `Theorem 9.1`)**: Three-term Cauchy-Schwarz + IEEE-754 directed-rounded upper bound (`R_head`, `R_copy`, `R_spread`, and slack `$\delta_{\text{slack}} = (d+8)\cdot 2^{-23}$`) with zero-sync GPU warp-ballot compaction (`__ballot_sync` + `__popc`), pruning 85%–97% of full-precision vocabulary rows with zero false negatives.
3. **Lossless Ensemble Speculative Decoding (`RAD-1`, `Theorem 10.1`)**: Online score-weighted ensemble combining a 262,144-token Suffix Automaton (`SessionIndex`), prompt suffix `Lookup`, and neural Multi-Token Prediction (`MtpDrafter`) with counterfactual EMA scoring and exact residual rejection sampling.
4. **Two-Tier `Warm Start` Prefix Caching & Hybrid Recurrent Rollback**: 256-token grid-aligned RAM/disk prefix caching across turns and sessions for both Transformer KV caches and hybrid recurrent architectures (`DeltaNetState` and `Mamba2State`), plus `Convoy` continuous batching and `Zero Wait` async host-device overlap.
+

* *Statement on alignment with LF AI’s mission.*
+
Swizzle AI directly advances LF AI & Data's mission to build and support an open, vendor-neutral, and trustworthy AI and data ecosystem:
+
1. **Vendor-Neutral Hardware Acceleration**: Runs from a single static Rust binary across CPU, NVIDIA CUDA, and cross-vendor Vulkan GPUs without proprietary runtime lock-in.
2. **Trustworthy, Reproducible & Auditable AI**: Enforces bit-exact deterministic output and emits cryptographic inference receipts (`swizzle-rt verify-receipt`), directly supporting LF AI & Data's Trusted AI initiatives.
3. **Open Standards & Interoperability**: Native support for open GGUF model weights and drop-in wire compatibility with OpenAI (`/v1/chat/completions`, `/v1/completions`, `/v1/embeddings`), `llama.cpp`, and Ollama endpoints.
